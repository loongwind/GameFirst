# P1-08 教学、任务与纪录海报实施计划

依据：LOO-57 启动交接、PRD §4.5/§11.1、技术方案 M1-10a。基线 5d0f67d，分支 loo-57-tutorial-tasks；直接沿用现有 Cocos / dispatch / 双槽存档，独立完成本轮实现。

## 设计与约束

采用持久化本地目标状态：教学进度、原 diveId 的单调深度/渊主/最终结算、任务实例领取键与纪录快照均随经济命令原子提交。单纯 telemetry.record 不产生任务资格。相比 UI 自行统计，此方案可刷新恢复且未来可迁移服务端；不引入另一套钱包或事件总线。

六步教学：首次启动直接 Dive；0–10 秒自动战斗，10–30 秒移动/真实击杀拾取，30–60 秒依次解释舱容和氧气，60–90 秒提示真实返航卸货，母港强化舱容/氧效后再潜，转为首日三潜目标。使用有效潜航时间，弹窗不阻断自动攻击。教程重放重新跑真实局，但固定首次领取键只发一次 500 荧晶，替代该教学局的荧晶而不叠加拾取收益。保留原始战斗与成长数值。

轮换条顺序采用累计 1000m、击杀 3 渊主、等级 50 的 PRD 样例，每实例只领一次；首日任务与轮换条并存，每次成功领奖增加 20XP。首日计数限首个业务日、原 diveId 真实击杀后主动返航最终结算；救援不终结局。

每 500m 持久打卡，刷新纪录在安全时段展示海报；本地 Canvas 程序绘制深度及已遇生物剪影，由 PlatformAdapter 保存 PNG。当前阶段 Web 无正式 AppID，不伪造小程序码。海报延后到结算/母港展示以避免战斗中反复暂停。
