# P1-02 战斗核心实施计划

依据：LOO-51、技术方案 §2.2、PRD §4.4/§5.2/§5.3。沿用 P1-01 Cocos 3.8.8 + TypeScript；此次执行已由 issue 授权，在指定 in-place 工作目录的新分支 `loo-51-battle-core` 完成。

## 设计与范围

选择纯 TS 数据世界和集中系统循环，拒绝逐怪 Component/刚体更新，也不引入 ECS 框架。`battle/` 仅允许 ES2020，无 DOM/Cocos/微信/数据库依赖。表现层只消费对象坐标及上一逻辑帧坐标，用 alpha 插值；输入为归一化向量。测试夹具使用 Canvas 并置于 `tests/fixtures`，不进入发布构建。

- `pool.ts`：预热定容池，单调 ID 防止回收后旧目标误命中；回收清理命中集合、事件及资源引用。
- `geometry.ts`：均匀空间网格、圆与圆/线段与圆精检，确定性最近目标选择。
- `model.ts`：数据契约、四武器参数、容量和随机数。
- `Battle.ts`：固定 1/30 秒累计器，最多追赶 3 步，丢弃超额整步；暂停及恢复清空积压；Spawn → Movement → Targeting → Weapon → Hit → Loot。
- `input.ts`：摇杆位移转向量；不接触事件或平台 API。
- `tests/battle.test.mjs`：直接编译运行实际 TS；`tsconfig.battle.json` 同时验证纯 ES2020 边界。
- `tests/fixtures/battle.html` / `battle-fixture.js`：可配置 40/80 怪、200 弹、100 掉落，四武器、摇杆、帧与逻辑耗时计数。
- `tests/battle-browser.mjs`：Chrome 下实际 rAF 压测、输入和无运行错误验收，生成截图/JSON。

索敌和远处怪朝向更新每 3 tick（10Hz），近处追踪每 tick；空间网格按怪体积占格。声波扩张环每目标一次，鱼雷直线扫掠且穿透不重复，链电每次施放独立命中集合且限制总跳数，浮雷独立容量、触发半径、爆炸半径和寿命。命中先于装饰生成，装饰池满只影响显示。怪池满延后刷怪，掉落满合并到最近堆保留总值，飘字满合并数值；弹池满保留武器待发状态。

参数为可替换的算法验证初值，不冻结 P1-04 经济平衡。氧气、局状态、结算及完整 Dive 视图不属于本 issue。

## 实施与验证顺序

1. 先写并运行池、几何、时钟/暂停/插值、seed/输入/索敌测试，确认缺失功能失败，再实现底层与循环。
2. 先写四武器、怪物死亡掉落、池耗尽及复用回归测试，确认失败，再实现系统；检查 40/80 两档运行不溢出、不产生无效数字。
3. 增加发布图外的可运行浏览器夹具和验收命令，记录持续饱和 80/200/100 下 rAF 间隔、逻辑耗时、更新及绘制耗时的 p50/p95/max。
4. 全量 `npm test`、`npm run typecheck`、纯数据类型检查、浏览器夹具、Cocos debug/release 构建及已有冒烟通过后做独立代码审查；只提交本任务文件。

## Review Focus

高速鱼雷穿越目标；空间格边界/负坐标/大半径；目标回收后的旧 ID；多段追赶与暂停恢复；装饰/掉落/弹体池饱和时真实伤害和资源守恒；链电有限跳且无重复；浮雷到期不误引爆；压测不能因运行中数量消退而成为空场景测量。
