# P1-02 战斗核心验证

日期：2026-11-10。基础工程：P1-01 `5075780`。本阶段交付纯数据算法与独立 Web 验证页；Dive 场景表现、氧气、局状态与结算由后续任务接入。

## 使用契约

入口 `assets/scripts/battle/index.ts` 导出 `Battle`、`Pool`、`SpatialGrid`、几何函数和 `joystickVector`。

```ts
const battle = new Battle({ seed: 7, weapons: [{ kind: 'sonic' }, { kind: 'torpedo' }] });
battle.setInput(0.6, 0.8); // 手动向量；超过单位长度会归一化
const { alpha } = battle.advance(renderDeltaSeconds);
const playerPosition = battle.samplePlayer(alpha);
// 其他对象用 previousX/Y → x/y 插值；只读使用，不保留跨回收的对象引用。
```

`step()` 推进单个固定 tick，供确定性回放。相同 seed（转换为 uint32，0 使用非零后备种子）、相同配置、相同逐 tick 输入与命令产生相同战斗状态；跨 JS 引擎的三角函数位级一致性不在保证范围。调用方记录逐 tick 输入，不能以渲染帧号记录回放。

`advance()` 以秒接收渲染间隔，最多推进 3 步，丢弃超额完整步并累计 `stats.droppedSteps`。`setPaused(true)` 冻结有效时间、清积压和输入；恢复后第一帧须由宿主重置时间戳，再从正常帧间隔调用。宿主将后台、广告、弹窗等原因聚合后调用，不能用一个原因结束解除其他暂停。`dispose()` 清所有池、命中集合、目标、网格及待处理数据；宿主同时清自己的表现节点和事件订阅。

所有池启动时定容预热。每类池内的 ID 单调递增，保存目标只用 ID，通过 `pool.get(id)` 重新解析；复用后的槽位不继承身份。实体不持有事件回调、UI 或资源句柄，队列只保存 ID/数值，回收时重置全部字段与 Set，销毁时清空网格。浮雷属于真实弹体池，具有独立挂载数量上限；装饰效果不会占用该池。

更新顺序固定为 Spawn → Movement → Targeting → Weapon → Hit → Loot。索敌与远处朝向更新每 3 tick（10Hz）。网格覆盖怪体积及本 tick 移动扫掠范围，鱼雷用相对移动线段精检，因此可检出怪物在 tick 内横穿弹道；近身接触伤害每怪每 30 tick 一次。普通怪没有刚体或全量怪对怪碰撞。

四武器参数在 `model.ts` 的 `WEAPON_DEFAULTS`，构造时可覆盖；这些是算法验证初值，数值配置接入由 P1-04 负责。`maxJumps` 表示一次链电最多命中的目标总数（包含首目标），每次施放去重；声波一轮扩张每目标最多一次；浮雷到寿命直接回收，不自动造成到期爆炸。自动攻击常开，不依赖广告声呐授权。默认两把主武器；夹具为覆盖算法显式同时启用四种。

池耗尽时：刷怪按后续 tick 重试，不积累无限刷怪队列；弹体不足时保留武器待发时间；浮雷受自身上限约束；掉落合并最近堆并保留总值；伤害飘字合并最近显示对象；装饰效果可省略。命中、死亡与掉落先完成真实数值处理，再消费显示容量。掉落值仅代表局内数值，不写账户、数据库或经济资产。

## 复现

在 `game/` 执行：

```sh
npm test
npm run typecheck
npm run typecheck:battle
npm run test:battle:web
npm run build:web
npm run test:web
npm run build:web:release
WEB_TARGET=web-release npm run test:web
```

手工查看：`npm run battle:serve`，浏览器访问输出的本地地址；Ctrl+C 停止。`?enemies=40&seed=7&stress=1` 和 `?enemies=80&seed=7&stress=1` 选择两档满载。取消满载勾选可观察普通战斗，左下摇杆、方向键或 WASD 控制移动，失焦/后台自动暂停。夹具与压力补充逻辑均在 `tests/`，不进入 Cocos assets 发布图，也不改变 Boot/Dive/Harbor。

浏览器验收启动临时 HTTP 服务及本机 Chrome，关闭浏览器和服务后退出，无遗留服务。每档预热约 45 帧、验证实际 pointer 摇杆位移，再记录 360 个 rAF 帧（约 6 秒）。逐帧维持所有压力对象，检查最小数量和真实击杀/命中，避免负载消退。相同的 Battle 代码用于自动武器和压力弹体，未替换碰撞或命中逻辑。

## 实测结果

环境：Apple M2 Max / arm64，Node 24.5.0，Cocos Creator 3.8.8，Playwright 1.56.1，本机 HeadlessChrome 157，视口 800×1000 / DPR 1。此为桌面浏览器算法与 Canvas 夹具记录，不代替微信真机或完整 Cocos 战斗场景性能验收。

| 负载 | 逻辑步 ms p50 / p95 / max | 帧 CPU ms p50 / p95 / max | rAF 间隔 ms p50 / p95 / max |
| --- | --- | --- | --- |
| 40 怪 / 200 弹 / 100 掉落 | 0.40 / 0.80 / 1.20 | 0.60 / 1.30 / 2.10 | 16.70 / 16.70 / 33.30 |
| 80 怪 / 200 弹 / 100 掉落 | 0.50 / 1.00 / 1.50 | 0.70 / 1.70 / 2.60 | 16.70 / 16.80 / 50.00 |

逻辑耗时是实际 `advance` 调用耗时除以当帧逻辑步数；帧 CPU 包括更新、夹具补充、Canvas 绘制及统计面板；rAF 间隔反映调度。两档均记录 360 帧、180 个含逻辑更新的帧，未丢步、无页面/console 错误。压力期间观测最小对象数分别保持 40/200/100 与 80/200/100。

自动门槛：逻辑步 p95 <8ms，帧 CPU p95 <16.7ms，rAF 间隔 p95 <40ms；实际机器资源竞争会影响结果。生成截图和 JSON 位于忽略的 `.artifacts/battle-{40,80}*`，交付时随 issue 附件提供。
