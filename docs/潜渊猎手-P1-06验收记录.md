# P1-06 声呐与情境广告点位验收记录

2026-11-10；基线 `76487e1`；任务分支 `loo-55-sonar-context-ads`。

## 交付行为

- 声呐只控制自动移动。每帧从既有 EconomyService 读取绝对到期时间 `buffs.sonarUntil` 的有效性，15分钟在后台、广告与暂停中照常流逝。剩余≤60秒可刷新为领取时刻起15分钟，不累加。基础自动索敌攻击继续使用原战斗系统，始终免费。
- `SonarSteering` 在纯数据战斗层执行16方向局部转向：优先退让危险区/接触威胁，拾取附近荧晶、接近敌人，绕开圆形障碍；低氧倾向上浮，满舱不追逐无法收纳的荧晶。手动向量与摇杆居中按住均立即接管，释放恢复有效声呐；到期回手动。环境随checkpoint保存，旧存档缺省为空环境。
- 潜航使用两处圆形礁石和一处危险区作为轻量局部环境，HUD同步绘制。无跨地图规划或自动返航策略。
- 低氧<15%出现局部供氧卡，不暂停、不拦截摇杆/返航。可“坚持上浮·关闭”，同低氧事件关闭状态随存档保存，成功补氧后下次低氧可再次提示。
- 救援面板真实按钮→AdService→持久化奖励→同diveId恢复50%生命且保留荧晶；拒绝救援按原死亡结算，仅清未卸货荧晶。供氧真实按钮成功后立即回满。两个点位各每日3次，计数与资格完全复用P1-04服务。
- `DiveAdModel` 只编排交互：观看前保存原情境，加载/播放与待确认期间冻结有效时间。无驱动、失败或跳过不发奖，可继续原选择/退出；已完成视频保存失败显示“重试原奖励”，沿原token/opId确认，不重复观看。
- 母港原 `configureAds` 保留；潜航增加 `configureAds(driver)`，保留 `createAdService(driver)` 兼容入口。默认无驱动，失败且无自动奖励。Mock实现仍仅在development/和测试图中，发布源码guard通过。

## 审查修复

独立审查发现并修复三条恢复路径：广告尚在播放时长断线不能先终结原情境；取消意图的保存失败在恢复存储后必须可重试取消；页面刷新时已在线也要先清除旧断线状态，再确认已完成/已领取的原奖励。针对后两项补充失败→通过的回归，第一项由Cocos延迟视频与31秒断线注入验证。复查无剩余阻断项。

截图检查另外发现氧气表与供氧按钮共用文字标识，已拆开并通过实际Cocos文字断言与截图验证。
